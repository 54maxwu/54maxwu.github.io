# 效能、AI 動作與精確回放紀錄

2026-11-15，本機實作與驗證，尚未發布線上版本。

## 渲染與量測

主要校園幾何依 24 m 空間格建立三角形索引，維持原本每材質合批；攝影機移動超過 0.3 m、轉動超過約兩度或投影改變才重新選取。可見範圍保留八公尺邊界，移動家具一律納入，裝飾繼續使用既有遠景細節策略。頂點與破壞範圍不重新編號，破壞／還原沿用原始資料。

陰影繪製使用另一份完整靜態索引，結束後恢復主攝影機索引，避免畫面外建築失去投影。這是視錐剔除，尚未加入房間遮擋剔除；站在室內，視錐內被牆遮住的其他建築仍可能提交。

曾實測每個區域拆成獨立網格的方案，因繪製呼叫大增而變慢，已移除該方案。採用版以同一場景、角色不更新、固定 1280×720 低畫質，交錯啟用／停用空間索引，三個視角各取六十次渲染樣本：

| 視角 | 原三角形 | 新三角形 | 繪製呼叫（前／後） |
| --- | ---: | ---: | ---: |
| 操場望校舍 | 1,178,144 | 732,302 | 175／175 |
| 走廊 | 1,178,038 | 631,532 | 122／122 |
| 全校俯瞰 | 1,186,662 | 1,185,882 | 191／191 |

操場與走廊提交量約下降 38%／46%；全校可見時沒有顯著減量。當次包含 GPU 完成等待的渲染中位數約為 22.7→22.4、10.7→9.9、37.4→38.6 ms，P95 未改善，不能據此宣稱整體 FPS 或卡頓已解決。數值受 headless Chrome、同機其他工作及 GPU 排程影響。一般遊戲迴圈另保留最近 300 幀的幀間隔、模擬／輸出 CPU 時間與幾何計數，供後續在目標裝置定位尖峰；不新增低於原生 CSS 尺寸的降解析度策略。

## AI 動作

- 連射數改由真正發射事件扣除，修正過去按模擬更新次數計數、射速受更新頻率影響的短點射控制。
- 遠距離使用較短連射，射擊前短暫站定瞄準，連射後停頓；半自動武器改用明確扳機節奏。
- 橫移方向維持 0.65–1.4 秒，移動輸入指數平滑，減少突然左右切換。
- 有合適掩體時短暫靠近，檢查附近約 1.4 m 的可站立、淨空與直線通行位置，探身觀察約 0.65 秒後返回掩體；受傷／換彈時優先退回。
- 探身只對最後觀察的威脅位置判斷遮蔽，真正開火仍需即時視線檢查；不取得隱藏敵人即時位置。仍為規則 AI，未加入神經網路模型。

## 精確事件與回放

保存射擊起點、命中點、部位、傷害、穿透旗標、來源 ID／姓名／隊伍副本。手雷與火箭以約 20 Hz 取樣軌跡，手雷明顯反彈及投擲物結束時額外保存位置。回放從致命事件取得起點與投擲物路線，避免攻擊者移動或重生後改變來源資料。

事件緩衝最多 512 筆且保留十二秒；投擲物最多 64 個，各最多 256 點。致命事件固定自己的軌跡副本，開新局清空紀錄。一般槍械命中線是真實判定，但瞬時射線沒有真實飛行時間，電影飛行仍標示為示意。爆炸的人體部位標記為代表點；校園破壞歷史尚未回溯。

## 驗證

45 項單元測試通過。瀏覽器驗證包含實際射線致命命中、攻擊者移動後回放起點不變、手雷爆炸回放取得十八個軌跡點、火箭實際飛行命中取得六個軌跡點、重開清空、30 秒八人加速模擬（觀察到探身狀態）、低／中畫質載入與陰影索引恢復。回放追蹤鏡頭靠近發射者頭部時隱藏該克隆，避免鏡頭穿進頭內。化雨臺、屋頂、粉刷牆、樓板、階梯破壞與還原正常；手機原生多指移動＋轉向＋射擊、獨立放開、縮放鎖定、武器循環與手雷操作正常，無 JavaScript 錯誤。

尚未以實體手機長時間發熱測試，亦未保證每款裝置固定 60 FPS。

## BVH 空間分割與陰影投射體剔除（2026-11-16）

`src/spatial-batches.js` 由 24 m 平面格改為每個材質一棵三角形 BVH（重心中位數切分，葉節點不超過 256 個三角形或 8 m）。三角形依深度優先順序排列，整棵子樹在視錐內時直接收下一整段索引；每材質仍只有一次繪製呼叫，頂點不重新編號。

- 選取用放寬 15°、外推 2 m 的視錐；每幀只檢查真實視錐的 8 個角是否仍在選取範圍內，仍在內就沿用，不重新上傳。選取視錐不用遠平面（攝影機 far 為 60 km，原本就沒有遠距剔除）。
- 重寫索引時只上傳與上次不同之後的部分；畫面外網格的待上傳範圍合併成一段。
- 陰影使用另一份索引：節點盒沿陽光方向延伸到地面，與畫面視錐不相交、或不在陰影攝影機範圍內的不畫進陰影圖。原本陰影每幀繪製全校約 115 萬個三角形。

碰撞（`campus-physics.js` 4 m 格 + DDA 射線）未改：實測射線、範圍查詢、站立判斷每幀合計約 0.65 ms，模擬總計約 2.3 ms，換成 BVH 收益很小。

### 量測

桌機 Chrome、中畫質、畫布 1766×742，遊戲暫停並固定攝影機。GPU 時間以 `EXT_disjoint_timer_query_webgl2` 量測；舊版為同一份原始碼只替換 `spatial-batches.js` 打包。

| 操場望校舍 | 1.96M → 1.58M | 244 → 177 | 17.2 → 15.2 |
| 望向校外街區 | 1.44M → 0.55M | 117 → 75 | 16.0 → 14.3 |
| 中庭 | 1.75M → 1.13M | 187 → 127 | 18.1 → 16.5 |

索引上傳：原地每幀轉 1° 轉一圈 380 → 285 MB；每幀前進 0.25 m 走 60 m，90 → 18 MB。該桌機新舊版畫面都維持 60 FPS（受螢幕更新率限制），手機尚未實測。

### 後續瓶頸

同一視角 GPU 約 17.9 ms；暫停陰影繪製降到 13.3 ms，解析度減半（像素剩 1/4）降到 9.1 ms。GPU 時間主要由像素決定，下一步優先考慮：陰影快取或縮小陰影範圍、檢查後處理與材質的像素成本、室內教室的遮擋剔除。
