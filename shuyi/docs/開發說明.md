# 樹義國小校園對戰：開發說明

網址：https://kd88.com/shuyi/ 。原始碼在 `../src`，建置方式見 `../src/README.md`。

## 1. 專案演進

1. 起點是 Minecraft 1.16.5 樹義國小存檔，轉成網頁方塊場景，接上一款開源 FPS 示範的槍戰與 AI。
2. 曾依 2016 年校園影片筆記修改方塊地圖立面（米黃牆、在大門穿堂設舞臺）。後來比對官網照片，發現與實景不符，已撤回。
3. 發現 Minecraft 地圖比例錯誤（每層 8 m、建築約 42 m 高，北側操場寬約 2 倍），表面修改無法做到 1:1。因此改以真實資料重建，也就是現在的 `campus-real.js`。
4. 加上教室分配（堂號＋班級門牌）、男生隊對女生隊、制服與體育服、全繁體中文，部署到 GitHub Pages。

## 3. 座標與方位

- 座標系：本地公尺，原點約在北緯 24.1117、東經 120.6570。遊戲中 x 為東、y 為上、z 等於負的北（z = -n）。
- 校地範圍：x -70~71，n -70~77（約 143 × 149 m）。四周為福田五街（北）、福田路（東，校門）、福田三街（南）、樹義五巷（西）。
- 舊 Minecraft 地圖相對實景旋轉了 90°：MC 西側 = 實際北側（操場、化雨台），MC 北側 = 實際東側（校門）。這只影響舊方塊場景，新場景已用正確方位。

## 4. 建築模型

| 棟 | 範圍（n 為北向座標） | 走廊側 |
|---|---|---|
| 義學樓（北） | x -48.1~42.5，n -11.4~3.2 | 南側（中庭） |
| 人傑樓（南） | x -49.7~41.8，n -56~-40.2 | 北側（中庭） |
| 樹德樓（東） | x 20.7~39.4，n -40.2~-11.4 | 西側（中庭），1F–2F 為挑高的大門穿堂 |
| 明哲樓（西） | x -50.3~-31，n -34.6~-16 | 東側（瑾瑜臺）；以 2F 以上的天橋連接北、南棟 |
| 樂群樓 | x 32.5~61.6，n 17~61 | 1F 桌球教室等，2F 禮堂，太子樓雙層屋頂，東北角鐘樓 |

- 樓高：1F 4.0 m，2F–5F 每層 3.6 m，屋頂 18.4 m，女兒牆 1 m。
- 房間位置：官網配置圖是示意圖、不按比例。做法是把每列的像素範圍（px 433~1462）線性對應到該棟 OSM 長度，見 `campus-real.js` 的 `PX()`。一間教室約 6.9 m 寬。
- `bar()` 產生每一棟：走廊 3 m（中庭側），房間在外側；1F 中庭側為磚拱廊，2F 以上為女兒牆加墩柱；外牆每層灰色水平帶、綠框窗，教室有陽台。
- 樓梯：雙跑樓梯，每跑 12 階（1F 每階 0.167 m，其餘 0.15 m），中間平台，頂樓有樓梯間（紅瓦頂）可上屋頂。
- 門寬 1.7 m：導航網格是 1 m 格，門太窄時格點進不去。
- 碰撞全部是軸對齊方塊。拱、屋頂等曲面只做視覺，碰撞用近似方塊。

## 5. 導航（AI）

- `CampusNav` 每 1 m 取樣可站立面，相鄰高差 ≤ 1.02 m 即相連。
- 實際比例樓梯的級高只有 0.15–0.17 m，原本從地面 0.04 m 起算的淨空檢查會撞到上一階，導致整座樓梯不通。實景場景改用 `clearY: 0.45`，在角色 0.55 m 的可跨高度以內。
- 驗證結果：四棟 1F–5F 都能從出生點導航到，約 92% 可站立面連通。玩家按 W 能走上樓梯到 2F；AI 依路徑走到 3F。
- AI 行為（`bots.js`）：目標點從全校可走區域（含樓上）隨機挑選；10 m 外看到敵人時邊走邊打，交火拖久會移動到側翼位置。

## 6. 隊伍與角色

- BL 為女生隊，穿制服：白色水手領上衣、深藍領與領巾、粉紅釦子、藍格紋百褶裙、白襪，長髮。
- GR 為男生隊，穿體育服：天藍 POLO、綠領白邊、白 V 襟、胸前寬綠帶上下白線、肩線細條、左胸校徽、及膝藍短褲側邊綠白黑條，短髮。
- 除了玩家「我」以外，依序命名為女同學1號、2號…，男同學1號、2號…
- 角色由程式產生（方塊、膠囊、球體綁在骨骼上，`character.js`）。格紋在貼圖集 x 512–640 的區段。

## 7. 介面與文字

- 介面與程式中的簡體中文，已用 OpenCC（cn → twp，臺灣用詞）全部轉為繁體。新增文字請直接寫繁體。
- 小地圖標籤顯示「樓名 樓層 · 堂號 班級」，例如「義學樓 5F · 齊陽堂 6-6」。判定依各房間的實際範圍（`realLocate`）。
- 教室門牌位在走廊側門上，底色依教室分配圖圖例：班級教室白、行政辦公室藍、專科教室紅、教學服務空間綠。

## 8. 每次更新前建議驗證

1. `npm run build` 沒有錯誤。
2. 在 repo 根目錄開靜態伺服器，進 `/shuyi/`：主控台出現 `CAMPUS_READY`，沒有 JS 錯誤或 404。
3. 開一局 4v4，確認雙方 AI 有移動與擊殺，計分正常。
4. 檢查位置標籤（例如走到義學樓 5F 西側教室應顯示「齊陽堂 6-6」）。
5. 改到建築或樓梯時，確認可以從 1F 走到 5F 和屋頂。

## 10. 已知限制

- 沒有建築圖：樓高、窗數、室內細節依照片估計；地下室停車場與電梯沒有做。
- 仁風臺依 115 學年度配置圖放在樹德樓 5F，外觀未經照片確認。
- 兩隊同時大量在室外交火時，AI 較少主動上樓。
- 遊戲引擎來源專案未附授權條款，公開前請自行評估或取得作者同意。
