# 回放架構參考與待辦

記錄日期：2026-11-15。以下為研究建議，尚未實作，也不代表已改善 FPS。

## demoinfocs-golang

來源：https://github.com/markus-wa/demoinfocs-golang

CS2／CS:GO demo 解析器，適合參考事件、狀態與軌跡資料設計，並非渲染或 AI 引擎。暫不直接整合 Go 套件。

- 用帶時間的戰鬥事件統一保存開火、受傷、擊殺、武器、命中部位、穿透資訊及精確命中點。
- 將角色姿勢短期快照與事件紀錄搭配，保存實際投擲物軌跡，以及構件破壞的時間與 ID。
- 回放應使用當時的場景狀態，逐步取代目前致命彈道示意與沿用當下破壞狀態的限制。
- 可從紀錄建立死亡熱區、武器統計及 AI 卡點分析；這些是後續自訂功能，不是套件會自動提供給本遊戲的能力。
- 記錄必須有時間／容量上限，避免為了回放新增長時間遊玩記憶體成長。

## demofile

來源：https://github.com/saul/demofile

CS:GO demo 解析器，提供 TypeScript／JavaScript、Node 與瀏覽器使用方式。GitHub 顯示於 2026-04-28 封存。作為設計參考，暫不加入依賴。

- 事件在 tick 結束、實體屬性完成更新後派送：本遊戲可借鏡一致的時間順序，避免回放讀到混合的新舊狀態。
- 將實體狀態、戰鬥事件與介面訊息分開管理；以穩定 ID 關聯角色、武器、投擲物和構件。
- 軌跡範例以投擲物生命週期追蹤位置，適合參考手雷／火箭的回放紀錄。
- 擊殺範例處理攻擊者已不存在的情況：本遊戲紀錄應保存攻擊來源資料副本，避免重生、重開或實體清除後誤認來源。

建議順序：先定義事件格式與時序，再做有上限的紀錄緩衝，接著驗證回放命中與投擲物一致性，最後評估破壞狀態回溯的記憶體與效能成本。畫面效能仍需另外量測渲染、碰撞、尋路與倒塌耗時。

## 首階段已實作（2026-11-15）

`combat-history.js` 已加入有上限的開火／命中事件與投擲物軌跡，保存攻擊來源資料副本及精確命中射線。回放使用致命事件的起點與軌跡，不再事後讀擊殺者槍口來推測。姿勢取樣移到該次模擬的手雷與火箭更新之後。這不是導入上述解析套件，也不是完整確定性重播。

待辦仍包括構件破壞的歷史回溯、死亡熱區及武器統計；目前一般槍械為瞬時射線判定，視覺子彈飛行仍明確標為慢動作示意，爆炸傷害部位以身體代表點顯示。
