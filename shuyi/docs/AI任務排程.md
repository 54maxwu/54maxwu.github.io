# AI 任務排程與整合

2026-11-16。開發於獨立 worktree，基底為主目錄當時未提交版本的快照；效能版本更新後，再同步其來源並整合 AI 變更。

## 修改範圍

- `game-src/bot-schedule.js`：任務完成／中斷、掩體動作與搜索觀察。
- `game-src/bots.js`：接入排程、保護非同步路徑回呼與重生生命週期。
- `game-src/bot-tactics.js`：掩體與探身點使用實際導航節點，避免角色到達路徑終點後，仍站不到原取樣點。
- `tests/bot-schedule.test.mjs`：八項排程與回呼回歸測試。

Half-Life 的任務排程概念僅作設計參考，未複製其原始碼。沿用現有 Three.js、尋路、視野、聽覺與武器系統，未加入神經網路。

## 行為

掩體動作依序為「移至掩體 → 觀察 → 視需要換彈 → 探身 → 短暫射擊 → 返回掩體」。普通聲音仍會記錄，但不會一直覆蓋尚未完成的掩體／換彈任務；真正看見敵人、受到傷害、掩體失效與路線超時有各自處理方式。

探身射擊窗口約 0.65 秒，失去視線或受到新傷害時提早返回。結構版本變更後檢查掩體與探身落腳點，失效時取消舊任務、路徑和殘餘移動輸入。連續四秒無進展的掩體路線會失敗退出，不永久停在待辦狀態。視覺記憶過期後停止依賴該位置。

到達最後觀察位置後短暫轉頭搜索約 1.1 秒，再清除該段記憶並回到巡邏。所有威脅位置來自既有感知快照；隱藏敵人的即時位置不提供給排程。

新路線送出時清除舊路線。每次請求與重生更新版本，過期回呼不得覆蓋目前路線；樓板失效時優先重算當前任務目的地，而非退回舊巡邏目的地。

## 診斷與驗證

`window.__game.actors` 中各 Bot 的 `schedule.task` 是目前任務，`schedule.trace` 最多保留 24 筆切換原因，重生清空；不做無上限的逐幀紀錄。

同步效能版本後共 58 項測試通過，其中新增八項測試涵蓋掩體序列、受擊中斷、換彈保持、掩體／樓板失效、路線超時、搜索記憶、過期路徑回呼與紀錄上限。

Chrome 本機八人對局以 1/60 秒步進進行兩次各 120 秒的加速模擬，不同隨機對局分別記錄到 113／54 次射擊，以及三次／一次掩體被破壞中斷。第二次使用最新效能來源建置，也驗證換彈完成及搜索結束回到巡邏；主目錄與 worktree 的整合建置雜湊一致（26ef0f531af4）。角色座標保持有限，重開重置正常，無 JavaScript 錯誤。此為功能回歸，不是實體裝置 FPS、長時間發熱或戰術勝率測試。

空間 BVH、索引更新、陰影篩選等效能來源採用另一邊完成的版本；本次 AI 開發未改寫其演算法。
